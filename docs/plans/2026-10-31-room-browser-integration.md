# 房间列表与加锁接入实施计划

**目标：** 完成 upgrade-room-lobby 的 2.1–2.3 和 4.1，保留 4.2 用户试玩。

**设计：** 复用 Studio 的 directory 与 room-browser。服务端显式投影公开消息，以连接请求的 IP 标识密码尝试，同一房间与 IP 串行验证。列表订阅即时返回首屏，后续在 tick 中最多每秒推送一次变更。客户端复用房间连接浏览列表，加入成功后退订；密码只留当前房间内存用于邀请链接，恢复连接只发令牌。

**技术栈：** 原生 ES 模块、Node 测试、ws、Vite、Playwright。

1. 服务端 RED：新增目录并发限次测试、房间协议测试和可信代理 IP 测试；运行 `node --test server/rooms/*.test.mjs` 确认缺失行为。
2. 服务端 GREEN：接入校验、房间元数据、订阅节流、销毁清理、异步加入与断线取消；再次运行上述测试。
3. 客户端 RED：补浏览订阅、错误重试、恢复不带密码、邀请参数与列表入口测试。
4. 客户端 GREEN：昵称置于列表上方；复用列表、建房与密码弹框；大厅显示名称与锁；合并中英文词条与深色金色样式；运行对应单测。
5. 验收：新增 `scripts/rooms-browser-e2e.mjs`，覆盖双页密码加入到倒计时、带密码邀请、满员禁用、列表无密码；输出四张指定截图并逐张检查。
6. 完成验证：`npm test`、`npx vite build`、OpenSpec 校验、检查任务勾选与 diff；提交中文说明并附 Codex 共同作者，不推送部署。
