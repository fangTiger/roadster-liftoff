# 三档机器人与大厅视觉实施计划

**目标：** 草甸三档约 41 / 37–38 / 34–35 秒，默认模拟与录像保持逐位兼容；房间列表复用三张赛道实景并改善标题对比度。

**架构：** 机器人单独缓存外—内—外赛车线，在该路径上做制动速度包络及追踪。先测中性车辆的策略上限，必要时由房主机器人显式传入引擎、极速和抓地倍率；默认均为 1。列表页使用 CSS 合成层淡入与轻量光效，不新增 WebGL 上下文。

**技术：** 原生 JavaScript、120Hz 确定性模拟、Node test、Vite、CSS、Playwright。

当前档位：简单、普通、困难，内部仅 easy / normal / hard。详细收敛步骤见 `2026-10-31-three-tier-bots.md`。

## 第一部分：三档机器人

1. 阅读既有驾驶、会话、物理、道具、测速脚本与 OpenSpec；保存默认黄金断言。
2. 新增赛车线几何、驾驶控制与性能隔离失败测试，执行 RED。
3. 实现仅机器人使用的赛车线/速度包络；用原车测走线、刹车、出弯油门及漂移策略上限。
4. 如目标仍不可达，加入显式中性的会话性能选项，验证真人/录像默认路径不变；校准三档。
5. 新增聪明道具失败测试，实现稳定瞄准、受锁护盾、弯前水雷、直道氮气。
6. 贯通服务端白名单、房间下拉、单人复用入口、中英翻译和名牌。
7. 三图三档各三次，六车混合同场三圈，困难每图十圈；报告平均、最快、加成及限制。
8. 更新 accelerate-personalize-bots 的规范和任务，严格验证后中文提交并署名。

## 第二部分：大厅视觉

1. 在现有房间列表测试中覆盖背景结构、空状态和减少运动。
2. 复用大厅深色、金色、橙红色设计变量，三图实景淡入、暗角、扫描光和光点；保留玻璃面板。
3. 加入房间行悬停、等待人数点呼吸、车辆空状态及建房按钮。
4. 标题局部渐变衬底及阴影，适配 390 宽与减少运动。
5. 桌面列表、空列表、手机列表、三张地图大厅标题截图逐张检查，测量列表帧率。
6. 全量 npm test、npx vite build、OpenSpec strict、diff 检查，中文提交并署名。

## 边界

不改 `.env`、私钥、SIM_VERSION、默认调校或用户未跟踪文件；不推送、不部署。两块独立实现并交叉检查，提交按上述顺序。
