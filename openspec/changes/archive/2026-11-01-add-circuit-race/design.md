# Design: 赛道竞速模式

## 场景（2026-10-28 更新）
- 用户认为沙漠景色不真实，改为瑞士阿尔卑斯山谷实拍全景（Poly Haven Alps Field，16K HDR 自行按 ACES 烘焙成 8 块分块）。赛道改名「阿尔卑斯环线」（Alpine Loop），盐湖段改为谷底高速段；第 3 批素材改选阿尔卑斯风格（针叶林、高山岩石、草甸）。
- 走线改为「直线 + 圆弧」描述（最小半径 22 m），见 src/race/track/data/desert-loop.js。

## 背景与约束
- 现有游戏世界是「跑步机」：车只做横向移动，世界向后滚动，公路是按里程左右摆动的正弦线，做不出急弯和闭合赛道。竞速模式需要一套真实二维世界坐标下的赛道、物理和镜头，放在新目录 src/race/，太空往返模式不动。
- 后续阶段要由服务器重放按键核实成绩，所以物理必须可重放：同一串按键在任何浏览器和 Node 里跑出完全相同的结果。
- 移动端也要能玩：新地图素材控制在 30 MB 以内，竞速模块按需加载。

## 模块划分（src/race/）
| 模块 | 职责 | 依赖 |
|---|---|---|
| `sim/fmath.js` | 确定性数学：多项式 sin/cos/atan2、整数哈希噪声。只允许 + − × ÷ 和 sqrt（IEEE 754 保证结果一致），禁止 Math.sin/cos/exp/pow 等 | 无 |
| `track/data/desert-loop.js` | 赛道数据：控制点（x, z, 高度, 路宽, 侧倾）、分段标签、检查点、机关位置、分支慢道 | 无 |
| `track/build.js` | 由控制点生成闭合向心 Catmull-Rom 中心线，按 1 m 采样为弧长表；生成地形高度场（2 m 网格）和地表类型图（柏油 / 路肩 / 沙地 / 盐湖 / 岩壁 / 峡谷）；墙体折线 | fmath |
| `sim/physics.js` | 车辆状态推进：纵向（动力、刹车、风阻）、横向抓地与漂移、地表摩擦、墙体碰撞（二维线段与圆）、离地与推进器、加速带、难度辅助 | fmath、track |
| `sim/hazards.js` | 机关：滚石、风滚草按比赛时间计算位置；锥桶、窄缝、断桥判定 | fmath |
| `sim/race.js` | 比赛流程：倒数、检查点顺序、圈数、圈速、罚时、方向错误、重置 | physics、hazards |
| `sim/replay.js` | 按键录制：每个模拟步一个按键位掩码，游程编码；记录模拟版本号与赛道哈希 | 无 |
| `scene/*.js` | 画面：地形网格（分块）、路面带、路肩、轮胎墙、机关模型、散布的植被和岩石、天空与光照、隧道光照变化 | three.js、track |
| `camera.js` | 竞速镜头：追尾（跟随车头、弯道外甩、速度拉远）、座舱、自由环绕 | three.js |
| `hud.js`、`results.js` | 圈数、圈速、最快圈、分段对比、小地图、倒数、方向错误；赛后成绩面板与上链入口 | i18n、chain |
| `index.js` | 竞速模式入口：加载、主循环（固定步长模拟 + 渲染插值）、暂停 | 以上全部 |

### 复用
- 车辆外观复用 `src/game/car.js`（车身、四组喷焰、姿态喷口、翻滚轴、刹车灯），只喂入新的位置、姿态和喷焰强度。
- 渲染器与后期复用 `src/game/engine.js`；天空与环境光复用沙漠 HDR（改为普通天空球，不再投影地面）。
- 金币外观复用 `src/game/coins.js` 的币面材质。
- 音频复用 `src/audio/`，补轮胎摩擦、撞墙、加速带音效。

## 确定性物理
- 固定步长 1/120 秒。渲染帧之间按累积时间推进若干步，画面在最后两步之间插值。
- 模拟输入每步一个位掩码：油门、刹车、左、右、推进器、翻滚、漂移、重置。
- 模拟状态只含数字，不引用 three.js 对象。模拟代码只用 fmath，单元测试在 Node 里断言「同一串按键跑两次结果逐位相同」，并保存一份固定的回放快照，防止以后无意改变物理。
- 版本号 `SIM_VERSION` 写进回放；改动物理时递增，旧回放不再用于核实。

## 车辆手感（初值，实测调整）
- 竞速调校与太空模式分开：极速约 300 km/h、刹车约 28 m/s²、柏油横向抓地约 1.6 g（街机手感）。
- 沙地：阻力大、抓地低；盐湖：抓地略低；路肩：轻微颠簸。
- 墙体碰撞：沿墙滑动，按撞击角度损失速度，不会卡死。
- 漂移：按住 Shift 降低后轮抓地、提高转向角速度；漂移时长分三档积攒加速，松开后释放。
- 推进器：离地上升，燃料有限；金币补燃料。
- 翻滚：竞速模式不使用（2026-10-28 用户决定，和第一版的感觉差距大）。物理里保留空中翻滚的实现，只是不映射按键。
- 漂移（2026-10-28 按用户反馈重做）：按住 Shift 并打方向进入，0.3 秒渐入；速度沿弧线转，弧线半径约为同速抓地转弯半径的 0.7 倍，打方向收紧或放宽；车头保持约 23° 侧滑角；按住漂移键按反方向键 0.1 秒切换为反向漂移；结束后 0.4 秒抓地逐步恢复。
- 二次加速：漂移超过 0.35 秒后结束，窗口内（标准 0.45 秒、新手 0.6、专业 0.3）松开再按油门，前冲 2.5 m/s 并加速 0.6 秒。
- 地图与难度（2026-10-28 用户澄清：三档难度 = 三张地图，不做辅助驾驶）：简单「草甸环线」（id 1，2.2 km，16 m 宽，平地，最小半径 45 m）、普通「湖畔环线」（id 2，2.1 km，发卡弯、坡顶小跳台、锥桶 S 弯）、困难「阿尔卑斯环线」（id 3，4.0 km，原赛道）。走线都由 src/race/track/turtle.js 的「直线 + 圆弧」生成，闭合由两段直线长度解二元一次方程求出；三张图共用阿尔卑斯天空。默认简单。
- 转向手感（2026-10-28）：方向盘变化速率 7/s、回正 9/s，转向与横向抓地按街机系数 1.5 放大，镜头朝向跟随速率 11，做到指哪打哪。
- 加速火焰：处在加速状态（加速带、漂移加速、二次加速）时车尾喷金橙色长火焰并点亮橙色光；压上加速带和二次加速的瞬间加冲击波环与视野猛张。
- 贴墙摩擦：接触墙的每一步速度乘 (1 - 0.8 × 步长)。

## 赛道与地形
- 中心线由约 60 个控制点生成；路面、路肩、墙体沿中心线按路宽和侧倾展开。
- 地形高度场 = 大尺度噪声 + 台地与峡谷造型 + 沿路面压平。地形和赛道都由同一份数据确定性生成。
- 分支慢道（峡谷绕行）作为独立的路段，与主线共用地表类型图；检查点只要求经过，不限定走哪条路。
- 赛道几何由我边看俯视图和行车画面边调；生成器先出俯视图预览脚本，方便迭代。

## 比赛流程
- 倒数 3–2–1–GO，GO 时开始计时。共 3 圈，取最快单圈。
- 检查点按顺序判定；越过终点线且 11 道检查点全部经过，记一圈。
- 方向错误：沿赛道反向行驶超过 2 秒时提示。
- 重置：掉入峡谷、车身朝下卡住超过 2 秒，或按重置键，回到上一道检查点，罚 3 秒。
- 赛后成绩面板：三圈用时、最快单圈、是否进入资格线、和自己最好成绩的对比，以及铸造 / 更新入口。

## 合约 V2：MarsRoadsterRacing（Arc Studio 编写）
- ERC-721 + ERC-5192，灵魂绑定（所有转让、授权调用都 revert），每个钱包最多一枚。
- 赛道配置（owner 设置）：`qualifyMs[trackId]`（资格线，0 表示未开放，可调高可调低）、`minLapMs[trackId]`（作弊下限，只能调高）。
- `submit(uint8 trackId, uint32 lapMs, uint32 achievements, uint64 deadline, bytes signature)`：
  - 赛道未开放 → revert；lapMs < minLapMs → revert TooFast
  - 设置了核实者地址时，必须附带核实者对（玩家、赛道、用时、成就、截止时间）的 EIP-712 签名，且未过期；未设置时签名参数忽略
  - 调用者没有 NFT：lapMs 必须 ≤ qualifyMs，否则 revert NotQualified；铸造 NFT，记录首圈（赛道、用时、时间，之后不变）
  - 每个（玩家，赛道）保存最快单圈与更新时间、是否经过核实；更快才更新
  - 成就 32 位，与已有位图按位或；没有任何变化时 revert NothingToUpdate
  - 先写状态再 `_mint`（吸取 V1 重入漏洞的教训），不用 `_safeMint`
- 只读：`recordOf(player)`（tokenId、首圈、成就、铸造时间）、`bestOf(player, trackId)`、`playerCount()`、`players(trackId, start, count)`（分页返回地址与该赛道最快单圈）、`tokenURI`、`locked`
- owner：`setTrack(trackId, qualifyMs, minLapMs)`、`setVerifier(address)`、`setBaseURI`
- 事件：`FirstLap(player, tokenId, trackId, lapMs)`、`LapRecorded(player, trackId, lapMs, improved, bestMs, achievements, verified)`、`Locked`、配置变更事件
- 测试网部署由 Studio 完成；主网用用户钱包部署（owner 为 0x81d48d2c5D0744e8eF7A5c35cDceB0A27A1c707B）。

## 前端链上对接
- `src/chain/` 改为 V2 接口：赛后若最快单圈在资格线内且未持有 NFT，显示「铸造首圈纪念 NFT」；已持有且更快或有新成就，显示「更新链上记录」；否则不发交易。
- 资格线、下限从合约读取，不在前端写死。
- 往返计时与相关上报代码下线；太空往返的成就照常解锁，可随下一次竞速提交一起上链。
- 链上记录面板：我的 NFT（首圈）、各赛道最快单圈、成就 n/28、三张地图各自的排行榜前 50。

## 风险
- **手感**：真实二维物理与镜头需要大量调校。对策：先做物理与镜头的灰盒原型（纯色地面 + 路面），手感过关再上美术。
- **跨引擎确定性**：只靠 fmath 和 IEEE 基本运算；Node 与 Chrome 的回放一致性写进测试，阶段 1 前再补 Safari、Firefox 实测。
- **性能**：4 公里赛道的地形分块加视距裁剪，植被用实例化，移动端降低密度。
- **成绩仍是自报**：阶段 0 资格线只能挡住普通玩家，按键录制为阶段 1 的核实做准备。

## 第 5 组收尾实现约定
- 当前 TRACKS 未提供资格线字段；外层 config.js 默认采用仓库 set-tracks 示例的 60 / 80 / 120 秒，赛道提供值时优先，成功读取链上配置后以链上值为准（0 不回退）。
- 成就从会话快照读取，沿用已有 1–20 号索引，新增 21–28 号；不修改确定性模拟。
- 竞速使用既有音频总线的纯合成模式，不加载新增音频文件。
