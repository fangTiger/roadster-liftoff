# 设计：派对竞速

## 原则
- 每台电脑只计算自己的车，机器人由房主的电脑计算。会影响别人的道具一律发消息，由被影响方的电脑自己判定、自己执行。
- 新机制全部是 session 的可选输入。不传时，单人模式和影子赛与现在逐位一致：golden 回归不变，SIM_VERSION 不变。
- 房间服务只做校验、限流、去重和转发，不算物理。

## 机器人
- 大厅里房主可以「加机器人」并选难度。服务端把机器人当成座位处理：带 bot:true 和 ownerId（房主），始终是已准备状态。房主可以移除机器人。
- 开赛后，房主的电脑为每个机器人各开一个 session：用发车格的出生点，输入用 autopilot 生成。机器人同样参与软碰撞、尾流和道具。房主按每秒 15 次代发 botState{botId,…}，服务端只接受该机器人所属房主发来的状态，然后像普通 peer 一样转发。
- autopilot 新增可选参数 `{cruise=1, cornerGrip=1}`，反应延迟由独立的 bot-driver 管理：
  - 简单：`{cruise:.82, cornerGrip:.8, reaction:18}`；
  - 普通：`{cruise:.9, cornerGrip:.9, reaction:10}`；
  - 困难：`{cruise:1, cornerGrip:1, reaction:4}`。
  - reaction 单位为 120Hz 物理步，初始转向队列填零；仅延迟转向位，油门、刹车和喷气即时生效，不传 opts 时 autopilot 输出保持逐位一致。
- 比赛中房主掉线：他的机器人记为未完成。在大厅里房主离开：机器人随之移除。
- 每次逐步只读 session.race 和 session.car，不用每次深拷贝的 snapshot。

## 尾流
- 判定条件：前车在自己车头方向 4–25 米内，横向偏差小于 1.6 米，两车朝向差小于 30°，自己车速大于 20 m/s。
- 满足条件时尾流槽按 1/1.2 每秒上涨，不满足时以 2 倍速度回落。槽满后清零，并给 draftBoost 秒的加速（用现有 boostTime 机制），产生事件 {type:'draft'}。
- 前车列表复用软碰撞的 contacts 回调（尾流判定前车时同样排除离地车和 ghost 车）。
- 参数加进 tuning：draftRange、draftWidth、draftCharge、draftBoost。

## 再来一局与表情
- 结算页的「再来一局」：回到大厅并自动发送 ready{on:true}。房主可在大厅换图、切换比赛模式。
- 表情：数字键 1–6 对应 👍 😂 🔥 😱 😎 🙏，发送 emote{id}。服务端对每人限流（1.5 秒一次）后转发。显示方式是车顶一个精灵图，持续 2 秒。

## 道具赛
- **模式**：大厅设置 mode ∈ {items, speed}，默认 items，在 start 消息中下发。
- **道具箱**：items.js 的 itemBoxes(track) 根据赛道确定性地生成位置。每圈 3 排，分别在赛道长度的 22%、52%、80% 附近，并避开 gap、slot 等特殊路段；每排横跨路面放 4 个。每个客户端各自判定自己是否捡到：半径 1.8 米，捡到后这个箱子在本机隐藏 4 秒。手里已经有道具时，箱子照样会被吃掉，但不换道具。
- **随机抽取**：按名次比例 p 取权重，p=0 为第一名，p=1 为最后一名：
  - 导弹：0.05 → 0.45
  - 水雷：0.40 → 0.10
  - 氮气：0.25 → 0.35
  - 护盾：0.30 → 0.10
  - 抽中后 HUD 播放约 1 秒的轮盘动画。只有 1 个道具槽。
- **效果**：session.applyEffect(kind, params) 排队，在下一步生效：
  - spin：导弹命中，持续 1.2 秒。立即把速度乘以 0.35，期间屏蔽油门、转向和漂移，车身做视觉旋转（只影响渲染，不影响物理航向）。
  - trap：水雷，持续 1.0 秒。速度归零，期间屏蔽所有输入，车外显示水泡。
  - nitro：boostTime 取 max(当前值, 2.0)。
  - shield：持续 5 秒。期间收到 spin 或 trap 时抵消一次，护盾破碎并产生事件。
  - 这些效果都不能让车的速度超过现有加速机制允许的上限。
- **导弹**：
  - 发射时锁定「比赛进度（圈数 × 赛道长度 + s）」比自己领先、而且距离最近的那辆车，范围 200 米内；没有目标就朝正前方飞 1.5 秒后消失。
  - 发 item{kind:'missile', itemId, from, target, firedAt}，firedAt 用模拟时间。各端按 1.5 秒的飞行时间，从发射者位置插值飞向目标当前的显示位置，并画出尾迹。
  - 目标端收到后立即显示「被锁定」预警。到了 firedAt+1.5 秒时，目标端执行 spin，或由护盾抵消，然后发 hit{itemId}；服务端去重后广播爆炸。
  - 目标掉线或已完赛时，导弹失效。
- **水雷**：
  - 投放在自己车后 3 米处，发 item{kind:'mine', itemId, from, x, z, placedAt}。
  - 存活 30 秒；投放后 0.6 秒才生效；投放者自己 1.5 秒内不会触发。
  - 各端判定自己的车是否在半径 1.6 米内；命中就执行 trap 或由护盾抵消，并发 mineHit{itemId}。服务端以先到为准，广播 mineGone{itemId, by}。两端几乎同时压上时可能都中招，这是可以接受的。
- **服务端**：
  - 只在 mode=items 且比赛中时接受道具消息；
  - 每人每 0.5 秒最多发一个道具；
  - itemId 由发送方 id 加序号组成，并检查唯一性；
  - 只做字段校验和转发，不算物理。
- **HUD**：顶部中间显示道具槽（含轮盘动画），另有导弹锁定预警（红框加提示音）、护盾倒计时、尾流槽。
- **特效**（程序生成，不依赖外部素材）：
  - 道具箱：旋转的发光立方体，带「?」贴图；
  - 导弹：锥体加尾焰，命中时爆炸；
  - 水雷：会晃动的蓝色水球；
  - 水泡：包住车的半透明球；
  - 护盾：半透明的六边形球壳。
- **音效**：拾取、轮盘、发射、锁定预警、爆炸、水泡、护盾破碎，都用现有的合成音效模块。

## 不做（本批）
- 两个道具槽、更多种道具、道具赛的成绩上链、观战。

## 第 1 部分实施计划与约定
- 按现有 OpenSpec 执行 1.1–1.4：先补失败测试，再依次实现再开与表情协议、尾流纯函数及会话、精灵和 HUD/音画反馈，最后全量测试与构建。
- 再开复用普通返回大厅流程，完成本地清理后发送 `ready{on:true}`；普通返回不发准备，沿用大厅的房主选图与全员准备开赛规则。
- 表情只在服务端 `racing` 阶段接受，非法 id 优先返回 BAD_MESSAGE，其他阶段返回 BAD_PHASE；每个玩家 1500ms 内最多一次，超限静默丢弃，身份由连接决定。广播包含发送者，本地也收到广播后才显示。
- 车顶表情使用独立 canvas 纹理与 THREE.Sprite，自己和远端共用；新表情替换旧表情，显示两秒、最后 0.3 秒淡出，换局、离开或销毁时释放资源。表情寿命按实际帧间隔推进，不受渲染平滑步长上限影响。键盘只接受 Digit1–6，忽略重复按键、输入控件、可编辑区域和暂停状态。
- 尾流新增 draftMin=4、draftRange=25、draftWidth=1.6、draftMinSpeed=20、draftCharge=1.2、draftBoost=0.8，既有参数不变。沿用确定性三角函数，将车头方向单位化并归一化角度，距离端点包含，横向、角差、速度严格比较；充满浮点边界允许 1e-12 的误差。
- contacts 只在原软碰撞前置条件成立时取一次，同一列表先碰撞再尾流；不传 others 不初始化 draft，不传 contacts 的单人路径与 golden 不变。空 contacts 的房间会初始化 draft=0，原快照比较测试只排除此新增字段。持续跟车可每充满一次再次触发，不按符合条件的前车数量重复发奖。
- 房间 HUD 在速度表附近显示 rh- 前缀的尾流槽，按模拟步记录 draft 事件并闪亮 0.3 秒；事件驱动短促上扬合成音及现有 boostFx.trigger。


## 第 2 部分实施约定
- 服务端机器人使用独立递增的 `b` 前缀 id，占用六席之一；只存 `difficulty`，不存本地化名字。room 消息包含 `bot`、`difficulty`、`ownerId`，results 保留 `bot`、`difficulty`，大厅、排名、结算、车顶名牌统一在客户端翻译，语言切换即时重绘名牌。
- `addBot` / `removeBot` 仅大厅房主可用，非房主返回 NOT_HOST，非大厅返回 BAD_PHASE，满员返回 ROOM_FULL，非法难度、botId 类型或移除非机器人返回 BAD_MESSAGE。增加机器人后沿用全员准备自动开赛规则；一位已准备真人和一位机器人即可开赛，结算后机器人保持准备。
- `botState` / `botFinish` 与真人复用字段白名单及 validState / validFinish；所属身份从连接与 ownerId 判断，不信任消息自报身份。未知、非所属或已失去连接的机器人返回 NOT_HOST；只在 racing 接收，state 在其他阶段静默丢弃，finish 返回 BAD_PHASE。每个机器人单独维护序列和每秒 30 条限流窗口，peer 发给同房其他真人，不回送所属房主；重复 finish 保留首次成绩。
- 机器人不参与网络广播出口、房主候选和真人恢复令牌。房主在大厅离开或断线移交时移除名下全部机器人（包括只剩自己时）；倒数或比赛中离开/断线则立即将未完赛机器人标为 DNF，已完赛成绩保留，旧机器人停止接收状态。回大厅移除失去所属房主的机器人，新房主不接管，旧房主重连也不复活；异步赛道加载结束后以最新 room 座位状态决定是否建立机器人 session。
- 房主为所属机器人建立独立 session、输入延迟队列和步数计数，使用 gridSpawn 和机器人 id 作为 contactId。逐步只读 session.car / session.race，不取 snapshot；每推进房主一物理步，机器人也各推进一步（每帧仍最多追 240 步）。按本轮座位列表的稳定顺序推进，接触列表直接读本机车当前状态，远端仍按模拟步采样、最多外推 250ms，过滤 stale、ghost 和离地状态；原软碰撞与尾流函数不改。
- 每个机器人独立按 15Hz 代发 botState，完赛后仍同步推进刹停并每秒重试 botFinish，直到统一结算；暂停只影响真人操控，不暂停机器人。返回大厅、换局或销毁时清空机器人，房主移交时立即停止旧机器人代发。
- `scripts/rooms-e2e.mjs` 默认仍是两个真人页面；`SCENARIO=bots` 使用一个带 autopilot 的真人页面，加普通、困难机器人，检查三条成绩、两条机器人 id 和全部完赛，不调用成绩核验或钱包。

- 本部分验证：全量 `node --test $(git ls-files -co --exclude-standard | grep -E '\.test\.mjs$')` 340 项通过，`npx vite build` 通过，`openspec validate add-party-race --strict --no-interactive` 通过；默认双页结算一致，`SCENARIO=bots` 三行全部完赛。简单地图独立三圈计时为困难 158.58 秒、普通 164.38 秒、简单 173.06 秒；原 autopilot 的 2000 步输入摘要回归通过。

## 第 3 部分实施约定
- 按 3.1–3.6 实施：纯函数和协议先补失败测试，随后接入固定步、HUD、共享资源特效和合成音效，最后执行全量回归、构建与机器人整局验收。沿用当前分支，不提交、不安装依赖。
- 房间默认 `mode:'items'`，大厅房主可发送 `pickMode{mode:'items'|'speed'}`；room / start 均携带 mode。竞速赛不建立道具控制器、道具实体、道具槽或球壳，软碰撞和尾流沿用原流程。
- 道具箱 id 为零起始的 `排号-序号`，每排以 1 米步长向前搜索，必要时绕回一圈；整排四点必须全在 ROAD。避开 gap、slot、ramp、rockfall、cones 和 boost 的实际范围并留安全距离（锥桶检查逐个 items，跳台检查全长）。横向四等距点使用路宽 80% 的有效横排宽度，宽路上限 13.2 米；道路边缘留空，内侧箱子也能被沿中线行驶的机器人拾取。高度跟随路面和倾斜。
- 每台本地模拟车辆（真人和所属机器人）各有一个槽及箱子刷新表，拾取和刷新按 `step * DT` 计时。抽取使用 `(rank-1)/(人数-1)`，单车取 0，排名沿用大厅座位稳定排序与比赛进度。房间默认注入 Math.random；纯函数和流程测试注入固定随机源。
- 真人轮盘持续一秒，期间不可使用；E 忽略重复按键、输入焦点、暂停、倒数及完赛，水泡禁锢期间也不能用道具。满槽仍消费箱子但不更换道具。机器人本批跳过轮盘，获得氮气、护盾或水雷即使用；导弹保留占槽，真人同样保留，下一批接发射。服务端当前只接受 mine，导弹消息待第 4 部分实现。
- `applyEffect(kind, params)` 将参数副本入队，下次 step 按先后顺序生效；仅调用过该接口才初始化 spinTime / trapTime / shieldTime。倒数中也消费队列并产生事件，但时长随实际物理步递减；完赛后不接受新的道具，已有时长继续过期。spin 清理残余转向、漂移与二次加速窗口，屏蔽油门、方向和漂移，瞬间保速 0.35，期间不允许速度回升；trap 屏蔽全部模拟输入、固定水平位置并在物理及接触后归零速度。氮气只复用 boostTime；护盾按队列顺序抵消首次 spin / trap，只有 shieldBreak，不发被抵消的 effect。视觉旋转只改车的渲染角度。
- 新增参数 spinTime=1.2、spinKeep=0.35、trapTime=1、nitroTime=2、shieldTime=5，既有参数和 SIM_VERSION 不变。不调用接口时车辆字段及黄金回放保持不变，physics / contact / draft 与比赛计时逻辑不改。
- state / botState 新增可选布尔字段 `shield` 和 `trapped`，服务端先校验再按白名单转发；新客户端始终发两个字段，旧客户端省略仍兼容。远端护盾和水泡采用这两个字段显示，不另发 effect 广播；自己的护盾倒计时从 session 读取。
- 机器人投雷、报命中复用 `item` / `mineHit`，附可选 botId；服务端必须验证 botId 为当前连接所属且仍连接的机器人，以真实 actor 身份填写 from / by，不能伪造。每台车独立按服务器实际时间限流 500ms，itemId 格式为 `自己的 id-正整数序号`，长度最多 64；每局保留全部已用 id 防重放，下一局清空。只在 items 且 racing 接受，已完赛或 DNF 的车不能继续投雷、报命中。
- 水雷投放音效立即反馈，实体等服务端向所有人（含发送者）回显 item 后再建立，避免被限流拒绝的投放留下本地幽灵雷。每端只检查自己及所属机器人；0.6 秒生效、本人前 1.5 秒豁免、半径 1.6 米包含边界、30 秒到期不再命中，均由纯函数判定。离地车不拾取、不压雷。命中在本机先播放爆开并排队 trap，删除本机实体，再发 mineHit；随后 mineGone 不重复播放。服务端保存首次 by，重复命中忽略；恢复连接重放未到期的存活 item 与已命中的 mineGone，同时补齐漏收实体和清除旧雷。
- 道具箱共享立方体几何及问号 canvas 纹理；水雷、水泡、护盾和远端加速尾焰共享几何/材质。箱子旋转悬浮，蓝色水球晃动，护盾为带三角网格的半透明球壳。返回、换局、结算和销毁时释放实体、球壳、爆开材质与纹理。氮气事件触发现有本机 boostFx；新增七类适中音量的合成音效沿用现有总线，效果音按事件游标防重播。
- `SCENARIO=bots` 明确选择道具赛；只对 rollItem 注入循环固定抽取值（其余随机仍保留），避免机器人保留导弹使本批三类可用道具验收随机漏测。通过出站 botState 的护盾/箱后加速及带 botId 的 mine 消息观察三类使用，检查三人成绩完整与无 pageerror，不调用核验、钱包或交易。

- 本部分最终验证：全量 `node --test $(git ls-files -co --exclude-standard | grep -E '\.test\.mjs$')` 369 项通过，黄金快照逐位一致；`npx vite build` 通过（保留现有依赖注释与大包提示）；`openspec validate add-party-race --strict --no-interactive` 通过。真实 Chrome 的 `SCENARIO=bots` 道具赛观察到 mine / shield / nitro，三车分别以 158.533、163.250、163.417 秒完赛，无 pageerror；另一次桌面截图检查无页面或控制台错误。只停止本次独立端口的服务，原有服务和本地配置不动。

## 第 4 部分实施约定
- 在当前分支按 4.1–4.3 实施；先补纯函数、控制器和服务端失败测试，再接渲染与音效。保留原物理、接触、尾流、比赛计时和既有 tuning 参数；不提交、不安装依赖。
- `pickMissileTarget(self, cars, trackLength)` 返回车辆对象或 null，车辆使用平铺的 `id/lap/s` 状态；累计进度为 `(lap-1)*trackLength+s`。严格领先且进度差不超过 200 米，取最近者；同进度、自己、完赛、ghost、stale、断线车辆排除，相同进度差沿用座位遍历顺序。
- 导弹与水雷共用每车的 item 序号、500ms 服务端限流和整局去重表。发射消息包含 `kind/itemId/target/x/z/yaw/firedAt`，机器人另附 botId；from 由服务端填写。target 必须显式为 null 或同房本轮仍连接、未完赛、非 DNF 的座位 id。发射实体和发射音效都由服务端 item 回显建立。
