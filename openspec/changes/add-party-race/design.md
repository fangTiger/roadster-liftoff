# 设计：派对竞速

## 原则
- 每台电脑只计算自己的车，机器人由房主的电脑计算。会影响别人的道具一律发消息，由被影响方的电脑自己判定、自己执行。
- 新机制全部是 session 的可选输入。不传时，单人模式和影子赛与现在逐位一致：golden 回归不变，SIM_VERSION 不变。
- 房间服务只做校验、限流、去重和转发，不算物理。

## 机器人
- 大厅里房主可以「加机器人」并选难度。服务端把机器人当成座位处理：带 bot:true 和 ownerId（房主），始终是已准备状态。房主可以移除机器人。
- 开赛后，房主的电脑为每个机器人各开一个 session：用发车格的出生点，输入用 autopilot 生成。机器人同样参与软碰撞、尾流和道具。房主按每秒 15 次代发 botState{botId,…}，服务端只接受该机器人所属房主发来的状态，然后像普通 peer 一样转发。
- autopilot 新增参数 {cruise, cornerGrip, reaction}：
  - 简单：巡航速度 0.82 倍，过弯偏保守；
  - 普通：0.9 倍；
  - 困难：1.0 倍。
  - 用转向延迟模拟反应，避免机器人走线完美得像录像。
- 比赛中房主掉线：他的机器人记为未完成。在大厅里房主离开：机器人随之移除。
- 每次逐步只读 session.race 和 session.car，不用每次深拷贝的 snapshot。

## 尾流
- 判定条件：前车在自己车头方向 4–25 米内，横向偏差小于 1.6 米，两车朝向差小于 30°，自己车速大于 20 m/s。
- 满足条件时尾流槽按 1/1.2 每秒上涨，不满足时以 2 倍速度回落。槽满后清零，并给 draftBoost 秒的加速（用现有 boostTime 机制），产生事件 {type:'draft'}。
- 前车列表复用软碰撞的 contacts 回调（尾流判定前车时同样排除离地车和 ghost 车）。
- 参数加进 tuning：draftRange、draftWidth、draftCharge、draftBoost。

## 再来一局与表情
- 结算页的「再来一局」：回到大厅并自动发送 ready{on:true}。房主可在大厅换图、切换比赛模式。
- 表情：数字键 1–6 对应 👍 😂 🔥 😱 😎 🙏，发送 emote{id}。服务端对每人限流（1.5 秒一次）后转发。显示方式是车顶一个精灵图，持续 2 秒。

## 道具赛
- **模式**：大厅设置 mode ∈ {items, speed}，默认 items，在 start 消息中下发。
- **道具箱**：items.js 的 itemBoxes(track) 根据赛道确定性地生成位置。每圈 3 排，分别在赛道长度的 22%、52%、80% 附近，并避开 gap、slot 等特殊路段；每排横跨路面放 4 个。每个客户端各自判定自己是否捡到：半径 1.8 米，捡到后这个箱子在本机隐藏 4 秒。手里已经有道具时，箱子照样会被吃掉，但不换道具。
- **随机抽取**：按名次比例 p 取权重，p=0 为第一名，p=1 为最后一名：
  - 导弹：0.05 → 0.45
  - 水雷：0.40 → 0.10
  - 氮气：0.25 → 0.35
  - 护盾：0.30 → 0.10
  - 抽中后 HUD 播放约 1 秒的轮盘动画。只有 1 个道具槽。
- **效果**：session.applyEffect(kind, params) 排队，在下一步生效：
  - spin：导弹命中，持续 1.2 秒。立即把速度乘以 0.35，期间屏蔽油门、转向和漂移，车身做视觉旋转（只影响渲染，不影响物理航向）。
  - trap：水雷，持续 1.0 秒。速度归零，期间屏蔽所有输入，车外显示水泡。
  - nitro：boostTime 取 max(当前值, 2.0)。
  - shield：持续 5 秒。期间收到 spin 或 trap 时抵消一次，护盾破碎并产生事件。
  - 这些效果都不能让车的速度超过现有加速机制允许的上限。
- **导弹**：
  - 发射时锁定「比赛进度（圈数 × 赛道长度 + s）」比自己领先、而且距离最近的那辆车，范围 200 米内；没有目标就朝正前方飞 1.5 秒后消失。
  - 发 item{kind:'missile', itemId, from, target, firedAt}，firedAt 用模拟时间。各端按 1.5 秒的飞行时间，从发射者位置插值飞向目标当前的显示位置，并画出尾迹。
  - 目标端收到后立即显示「被锁定」预警。到了 firedAt+1.5 秒时，目标端执行 spin，或由护盾抵消，然后发 hit{itemId}；服务端去重后广播爆炸。
  - 目标掉线或已完赛时，导弹失效。
- **水雷**：
  - 投放在自己车后 3 米处，发 item{kind:'mine', itemId, from, x, z, placedAt}。
  - 存活 30 秒；投放后 0.6 秒才生效；投放者自己 1.5 秒内不会触发。
  - 各端判定自己的车是否在半径 1.6 米内；命中就执行 trap 或由护盾抵消，并发 mineHit{itemId}。服务端以先到为准，广播 mineGone{itemId, by}。两端几乎同时压上时可能都中招，这是可以接受的。
- **服务端**：
  - 只在 mode=items 且比赛中时接受道具消息；
  - 每人每 0.5 秒最多发一个道具；
  - itemId 由发送方 id 加序号组成，并检查唯一性；
  - 只做字段校验和转发，不算物理。
- **HUD**：顶部中间显示道具槽（含轮盘动画），另有导弹锁定预警（红框加提示音）、护盾倒计时、尾流槽。
- **特效**（程序生成，不依赖外部素材）：
  - 道具箱：旋转的发光立方体，带「?」贴图；
  - 导弹：锥体加尾焰，命中时爆炸；
  - 水雷：会晃动的蓝色水球；
  - 水泡：包住车的半透明球；
  - 护盾：半透明的六边形球壳。
- **音效**：拾取、轮盘、发射、锁定预警、爆炸、水泡、护盾破碎，都用现有的合成音效模块。

## 不做（本批）
- 两个道具槽、更多种道具、道具赛的成绩上链、观战。

## 第 1 部分实施计划与约定
- 按现有 OpenSpec 执行 1.1–1.4：先补失败测试，再依次实现再开与表情协议、尾流纯函数及会话、精灵和 HUD/音画反馈，最后全量测试与构建。
- 再开复用普通返回大厅流程，完成本地清理后发送 `ready{on:true}`；普通返回不发准备，沿用大厅的房主选图与全员准备开赛规则。
- 表情只在服务端 `racing` 阶段接受，非法 id 优先返回 BAD_MESSAGE，其他阶段返回 BAD_PHASE；每个玩家 1500ms 内最多一次，超限静默丢弃，身份由连接决定。广播包含发送者，本地也收到广播后才显示。
- 车顶表情使用独立 canvas 纹理与 THREE.Sprite，自己和远端共用；新表情替换旧表情，显示两秒、最后 0.3 秒淡出，换局、离开或销毁时释放资源。表情寿命按实际帧间隔推进，不受渲染平滑步长上限影响。键盘只接受 Digit1–6，忽略重复按键、输入控件、可编辑区域和暂停状态。
- 尾流新增 draftMin=4、draftRange=25、draftWidth=1.6、draftMinSpeed=20、draftCharge=1.2、draftBoost=0.8，既有参数不变。沿用确定性三角函数，将车头方向单位化并归一化角度，距离端点包含，横向、角差、速度严格比较；充满浮点边界允许 1e-12 的误差。
- contacts 只在原软碰撞前置条件成立时取一次，同一列表先碰撞再尾流；不传 others 不初始化 draft，不传 contacts 的单人路径与 golden 不变。空 contacts 的房间会初始化 draft=0，原快照比较测试只排除此新增字段。持续跟车可每充满一次再次触发，不按符合条件的前车数量重复发奖。
- 房间 HUD 在速度表附近显示 rh- 前缀的尾流槽，按模拟步记录 draft 事件并闪亮 0.3 秒；事件驱动短促上扬合成音及现有 boostFx.trigger。
